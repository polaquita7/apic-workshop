Escenario y contexto

En este lab vas a crear una API proxy que expone el endpoint /catalog-nn y redirige las llamadas al servicio https://148.100.75.105:9443/catalogManager/items?startItemID=10. El DataPower API Gateway aplica la política Invoke para hacer el reenvío hacia el backend, devolviendo la respuesta JSON al cliente original.

Pasos del laboratorio

Paso 1 — Ir al IBM API Studio desde el dashboard

1
Abrir el API Studio desde el API Manager

Desde el dashboard del API Manager, hacé click en el ícono API Studio (lápiz) en la barra lateral izquierda.

Paso 2 — Crear un nuevo proyecto

Nuevo en APIC v12 — Proyectos Un Proyecto agrupa todos los recursos necesarios para diseñar, publicar y probar una API: definiciones, políticas, entornos y configuraciones de prueba. Se gestiona como una unidad a lo largo de todo el ciclo de vida.
2
Crear un proyecto en blanco

Hacé click en el botón New API project en la esquina superior derecha y elegí la opción Create blank project.

3
Completar el formulario del proyecto

Completá los datos del nuevo proyecto:

CampoValor
Project namemi-primer-proyecto-nn
StorageNative storage (seleccionado por defecto)

Hacé click en Create.

El nuevo proyecto aparecerá primero en la lista. Hacé click sobre el nombre para abrirlo.

Paso 3 — Agregar una API

4
Iniciar la creación de una API REST

Hacé click en Add an API + (o en el ícono + al lado de APIs en el panel Explorer de la izquierda).

Seleccioná la opción Create a REST API.

Elegí la opción From scratch para crear una API desde cero.

Paso 4 — Completar los datos de la nueva API

5
Ingresar nombre y versión de la API
CampoValor
API namecatalog-nn
Namespacese completa automáticamente con el nombre del proyecto
API version1.0 (valor por defecto)

Hacé click en Create.

Paso 5 — Agregar un path

Nuevo en APIC v12 — Explorer y Outline
  • Explorer: muestra todos los assets del proyecto — APIs, policies, tests, assertions y otros recursos relacionados.
  • Outline: organiza la estructura de la API en secciones (General information, Paths and Operations, Security, etc.) para navegar y editar su definición de forma ordenada.
6
Ir a Paths and Operations y agregar un path

En el menú Outline de la izquierda, hacé click en Paths and Operations. Hacé click en Add path +.

7
Completar el formulario Add path
CampoValor
Path/catalog-nn
Supported Operations✅ GET
Summary / Descriptiondejar vacío

Hacé click en Add.

El path /catalog-nn aparecerá en la lista de rutas.

Paso 6 — Agregar una respuesta HTTP a la operación GET

8
Abrir el detalle de la operación y agregar respuesta

Hacé click sobre el path /catalog-nn para ver el detalle de la operación. Scrolleá hasta la sección Responses y hacé click en Add response.

9
Completar el modal Add response
CampoValor
Status code200
DescriptionOK

Hacé click en Add.

Paso 7 — Crear una Policy Sequence

10
Agregar una Policy Sequence desde el Explorer

En el panel Explorer de la izquierda, hacé click en el ícono + al lado de Policy sequences.

Nuevo en APIC v12 — Policy Sequences Definen el orden en que las políticas se aplican a una API durante el procesamiento de requests y responses. El tipo depende del gateway destino:
GatewayTipoDescripción
DataPower API GatewayDataPowerAssemblyPolíticas como acciones de procesamiento dentro de un ensamblado, en el orden exacto configurado.
DataPower Nano GatewayFreeFlowPolicySequenceDefinición flexible y personalizada del orden de ejecución.
webMethods API GatewayStagedPolicySequencePolíticas organizadas en etapas predefinidas con orden fijo.
En este lab usamos DataPower API Gateway, por lo que la policy sequence será de tipo DataPowerAssembly.
11
Completar el formulario Add policy sequence
CampoValor
Select GatewayDataPower API Gateway
Policy sequence namecatalog-nn-ps
APIcatalog-nn (la API que creaste)

Hacé click en Add. La nueva policy sequence aparecerá como asset en el panel Explorer dentro de Policy sequences.

Paso 8 — Configurar el Invoke

12
Abrir el Assembly Canvas

Al hacer click en la policy sequence creada, se abre el Assembly Canvas con una política Invoke ya creada por defecto y la paleta de políticas disponibles en la parte inferior.

13
Configurar la política Invoke

Hacé click sobre el bloque Invoke para acceder a sus configuraciones y completá los siguientes datos:

CampoValor
URL
Username
Password

Paso 9 — Publicar la API

14
Iniciar la publicación desde la barra superior

Cuando estés listo, hacé click en Publish en la barra superior derecha.

15
Configurar el destino de publicación

En el formulario que se abre, elegí las siguientes opciones:

CampoValor
Assets to publishAPI assets (opción por defecto)
CatalogSandbox
Available gateways✅ DataPower API Gateway service (desmarcá el nano-gateway si estuviera tildado)

Hacé click en Next.

16
Confirmar los assets y publicar

Dejá todos los assets marcados y hacé click en Publish.

Esperá unos segundos hasta que aparezca el mensaje de confirmación.

Paso 10 — Probar la API

17
Abrir el Tryout

Volvé a elegir tu API catalog-nn | 1.0 en el Explorer y hacé click sobre el botón Tryout en la esquina superior derecha.

18
Enviar la petición de prueba

Desplegá la lista Server y elegí la opción que termina con sandbox. Dejá los demás valores por defecto y presioná el botón Send.

19
Revisar la respuesta

Si todo está correcto, vas a recibir una respuesta JSON. La respuesta siempre incluye el código de estado HTTP y el tiempo de respuesta. Hacé click en la pestaña Body → Parsed para ver la respuesta formateada.

Tracing de la ejecución En la pestaña Trace podés ver exactamente cómo se ejecutó la llamada a la API, paso a paso. Es muy útil para depurar errores.

Si preferís probarlo desde la terminal, usá el botón Copy as cURL:

curl \
  -X GET \
  '...' \
  -H 'Content-Type: application/json' \
  -H 'Apim-Debug: true'

Verificación

Al finalizar este laboratorio deberías poder:

  • Crear una API REST que funcione como proxy a un backend no securizado.
  • Publicarla en IBM DataPower API Gateway.
  • Probarla desde el API Studio o tu terminal y recibir una respuesta JSON válida.
